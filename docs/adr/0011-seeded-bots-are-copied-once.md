# Seeded Bots are copied once and then belong to the Members

Hamkey ships its starting Bots, such as the meal planner, as ordinary Bot files in `seeds/bots`. At startup `seedBots()` copies each into `<dataDir>/bots` if its id is not yet listed in `<dataDir>/seeded.json`, and then lists it. A file that already exists is never overwritten (it counts as seeded), and a Bot a Member deletes is not recreated, because the id stays listed. There is no code path that treats a Seeded Bot differently afterwards: the meal planner uses only the tools its file names (memory, `research`, `ask`, `ask_choice`) and never web tools.

Built-in Bots (Primary Bots, Research Bot) are the opposite: defined in code, not editable. Seeding was chosen for the meal planner because spec story 31 asks that Seeded Bots have no special status, and because a Member may want to change its instructions. The cost is that improvements to the shipped instructions do not reach a data folder that already has the file; a Member who wants them copies them in by hand. Keeping `examples/` for fixtures that tests copy, and `seeds/` for what ships, stops a test fixture from becoming a shipped Bot by accident.
